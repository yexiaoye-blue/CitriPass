# ADR-005：主密码轮换与恢复密钥

- 状态：已接受
- 日期：2026-10-12

## 背景

`docs/03` 第 5 节要求：创建保险库时生成恢复密钥并要求用户确认已保存；更换主密码时只重新包装 Vault Key，不重加密所有条目。`docs/08` 的 Milestone 0 把「验证密钥轮换」列为完成条件。

`vault-core` 第一刀只实现了主密码一条包装路径，条目加密用的是 Vault Key、不是 KEK，为轮换留好了空间，但轮换和恢复本身还没有实现，也没有测试。

## 决策

1. 创建保险库时同时生成两条互不相干的包装路径：主密码派生 KEK、恢复密钥派生 KEK，两者都只包同一把随机 Vault Key。改主密码或换恢复密钥都只重写自己那一份包装。
2. `change_master_password(old, new)` 必须先验证旧密码，然后用新的 salt 重新派生 KEK 并重新包装同一个 Vault Key。条目密文一个字节都不动，恢复密钥也不受影响。
3. `reset_recovery_key()` 生成并包装一把新恢复密钥，旧的那把无法解开更新后的恢复包装；已有旧快照仍可由旧密钥解开；主密码不受影响。
4. 两条路径的 AAD 使用不同用途标签（主密码 `citripass.vault-key.v1`，恢复密钥 `citripass.recovery-key.v1`）再拼 `vault_id`。只绑 `vault_id` 的话，恢复块可以被整体挪进主密码槽，造成解锁错乱。
5. 恢复密钥由 core 用操作系统 CSPRNG 生成，随机源失败返回错误。`RecoveryKey` 不实现 `Clone` 和 `Display`，`Debug` 脱敏，Drop 时清零。文本按 4 字符空格分组，返回 `Zeroizing<String>`；完整保留 base64url 字母表，`-` 和 `_` 是数据，不能丢弃。旧实现按字符重抽会缩小密钥空间，“不损失熵”的判断不成立，现已删除该过滤。
6. 恢复密钥沿用 Argon2id（带自己的 salt），不引入第二条 KDF 实现。32 字节随机值本来不需要拉伸，这里选了「只有一条 KDF 路径、共用同一套参数校验」的简单性；代价是恢复解锁多跑一次 Argon2id（19 MiB、t=2）。
7. JSON 外壳新增可选的 `recovery` 块，缺省读成 `None`：第一刀写出的文件仍然能用主密码解锁。老代码读带 `recovery` 的文件会因为 `deny_unknown_fields` 拒绝解析，不会误读。因此 `format_version` 保持 1。一旦 v1 正式发布，再加字段就必须同时升版本并保留两代读取路径。

## 影响

- 改主密码是 O(1)：不随条目数量增长，也不产生新的条目密文版本，但包装元数据需要保存和同步到其他设备。
- 忘记主密码时可以用恢复密钥解锁；两样都丢仍然无法解密，`docs/03` 第 4 节的限制不变。
- 用恢复密钥解锁不修改任何落盘内容。用户借恢复密钥进入后，可以使用 `reset_master_password(recovery_key, new)` 验证恢复凭据并重设主密码，无须旧主密码，再换一把恢复密钥。
- 恢复密钥是一条离线秘密，泄漏等于拿到整个保险库。产品层必须要求用户抄写并确认已保存（界面尚未实现）。
- 未来按 `docs/03` 第 1 节增加 Device Key 包装时，照同一模式挂第三条路径，并在 AAD 里再加一个用途标签。

## 2026-10-12 核心库完善

新增经过恢复密钥验证的密码重设；改密码保留原有 Argon2id 调优并更换 salt。Device Key 包装单独保存在本机，不自动同步。恢复轮换不会撤销已复制的 Vault Key、旧备份或其他已解锁会话，泄露后的全库密钥轮换需要独立设计。实现与验证边界见 `vault-core/GUIDE.md` 和 ADR-006。

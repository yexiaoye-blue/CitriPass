# ADR-006：核心领域模型、独立密文和附件边界

- 状态：已接受
- 日期：2026-10-12

## 背景

早期 vault-core 把登录条目和整个库 JSON 捆在一起，只证明基础加解密。研发方案要求多类型条目、逐条持久化与同步，以及独立的大附件加密；恢复解锁也需要在没有旧主密码时完成主密码重设。

## 决策

1. Rust 核心负责领域模型、格式、密钥生命周期、单条 AEAD、密码生成、TOTP 和附件块的认证；存储、账号认证、系统认证及网络由适配器负责。
2. 领域内容用 `ItemDraft` / `ItemData` 表示，包括登录、笔记、TOTP、卡片、身份和文件夹。标签、自定义字段、文件名等都在加密 body 内，不新增明文索引。
3. 外层 AEAD 格式 v1 不变，明文 body 独立采用 schema_version 2。读取旧登录 body；只在修改条目时迁移。旧密文保持原样，未知版本拒绝。
4. `EncryptedItem` 允许逐条存储/同步；导入先认证，再以期望版本比较更新，并拒绝回退及同版本不同内容。数据库原子性、服务器游标和冲突副本由相应适配器处理。
5. 新建可选择更强的 KDF 调优；改密码不能悄悄降级原参数。恢复重设验证恢复密钥，重新包装同一 Vault Key。
6. 备份快照用单独用途的 AEAD 认证完整密文集合摘要，检测条目清单删改。普通 SealedVault 是持久化/同步容器，不提供整体清单认证。核心快照不含附件块；完整归档及附件清单仍由备份适配器负责。
7. 附件采用 RustCrypto STREAM BE32 + XChaCha20-Poly1305，独立随机 DEK、19 字节 nonce、64 KiB 块及认证终块。包装同时认证库/条目/附件 ID、版本、大小和 nonce。加密会话不可恢复或复制；上传续传使用已保存的密文块。
8. 本机 Device Key 包装与可同步元数据分开，必须由平台安全模块保管密钥并执行系统认证。
9. 通过 Zeroizing/ZeroizeOnDrop 清理核心拥有的秘密和缓冲、清理 Argon2 工作内存，并脱敏所有明文 Debug。调用方持有的副本和系统缓存仍由调用方清理，不能承诺整个进程绝无秘密残留。

## 验证与限制

固定加密向量由独立 libargon2/libsodium 生成，TOTP 对照 RFC 6238 SHA-1/256/512 向量；测试还覆盖失败原子性、冲突、篡改、旧格式及附件损坏/截断/错序。

合法旧数据库/备份的完整回滚需要外部可信状态；密码/恢复包装轮换不撤销旧快照或已复制的 Vault Key。WASM 编译检查不能替代浏览器运行、FFI 接入和跨设备验收。尚未完成独立安全审计或持续模糊测试。

详细接口及格式见 [vault-core/GUIDE.md](../../vault-core/GUIDE.md)。

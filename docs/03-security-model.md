# CitriPass 安全与密码学模型

## 1. 密钥层级

```text
主密码
  ↓ Argon2id + 用户独立 salt
KEK（Key Encryption Key）
  ↓ 解包
Vault Key（随机生成的保险库密钥）
  ↓ AEAD
条目密文、TOTP 密文、附件密钥
```

设备本地可以额外使用系统生成的 Device Key 包装 Vault Key：

```text
Vault Key
  ├── 由 KEK 包装，支持主密码恢复
  └── 由 Device Key 包装，支持本机快速解锁
```

Device Key 存入系统 Keychain、Android Keystore、Windows Credential Manager 或同类安全存储，不上传到服务端。

## 2. 加密要求

- 使用经过验证的 AEAD 方案，例如 AES-256-GCM 或 XChaCha20-Poly1305。
- 每次加密都生成唯一 nonce，禁止复用同一个 `key + nonce`。
- 密文携带版本、算法、nonce 和认证标签。
- 条目和附件使用独立的关联数据绑定 `vault_id`、`item_id`、`revision`，防止密文被跨对象替换。
- 大文件使用流式认证加密，不能先整体读入内存。
- 密钥由操作系统安全随机源生成，不能由用户可控文本直接生成。

## 3. 主密码与账号认证

主密码用于客户端派生 KEK，不应成为普通 API 登录密码的唯一实现。

账号认证应优先采用成熟的 OPAQUE、WebAuthn/Passkey 或经过验证的身份服务。若早期版本采用独立账号密码，应明确区分：

- 账号密码：服务端认证和会话；
- 主密码：客户端解锁保险库。

服务端绝不能因为能够验证账号登录，就获得 Vault Key。

## 4. 威胁模型

### 主要防护目标

- 服务端数据库泄露；
- 服务端备份和对象存储泄露；
- 网络传输被监听或篡改；
- 恶意同步客户端提交伪造版本；
- 本地数据库文件被离线复制；
- 云端附件被直接下载。

### 明确限制

- 已完全控制用户设备的恶意程序可能在解锁期间读取明文或密钥；
- 恶意浏览器扩展或被攻陷的浏览器可能影响自动填充；
- 弱主密码仍会受到离线猜测攻击；
- 用户丢失所有解锁方式和恢复材料后，零知识模型无法代为解密。

## 5. 恢复与轮换

- 创建保险库时生成恢复密钥或恢复包，并要求用户确认已保存。
- 更换主密码时只重新包装 Vault Key，不重加密所有条目。
- 设备撤销后，服务端拒绝该设备继续拉取和提交同步。
- 修改加密格式时保留旧版本读取能力，完成迁移后再升级写入格式。
- 恢复密钥不能写入普通日志、剪贴板历史或分析事件。
